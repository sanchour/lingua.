### 6-25 · Accessibility/desktop · unsafe/incomplete paths found in source

1. **“Clear cached media” deletes saved media too, without undo.** `StorageSection.tsx:33–38` calls `db.blobs.clear()` across all languages and blob kinds. This is also where imported card media and learner recordings/audio are stored. There is no cache-only filter, confirmation or recovery in this handler. It was **not clicked**. Treat as a data-loss risk; replace with safe classification and recovery before testing deletion. The breakdown counts dictionaries/books/cards/blobs, not the promised packs/voices/audio/video/recordings with separate deletion.
2. **Privacy copy makes unsupported promises.** `StorageSection.tsx:116–128` says learner text never leaves except sync/export, and providers never store/train on AI or keep recordings. Opt-in AI can send learner text, and these provider retention promises are not enforced by this app. Browser-native speech recognition may also use the browser vendor's services; `listenOnce` does not request on-device-only recognition. This needs accurate, conditional destination disclosure, not unverified external-policy guarantees.

The on-device Whisper job/worker (`services/transcribe/device.ts`) and speech recognition (`services/speech/recognition.ts`) have no matching visibility pause/cancel path; the Diarium handler flushes writing activity, not transcription. Live-radio and real transcription behavior were not exercised. Do not equate stopping spoken output with pausing speech-to-text.
4. **The floating review is not a working review session.** `DailyWordCard.tsx:127–162` builds a word/gloss/count/link view; it does not reveal/grade cards. The fallback shows one word and a timer. The floating window's Full Review link is rooted at `/thesaurus/...`, omitting the deployed `/lingua./` base, and the control is shown without the required support-only guard. Chrome/Edge Document PiP and notification permissions were not tried.
5. Accessibility runtime diagnostics: the browser reported nested `<button>` elements in TodayCard's Ludus/PlusChip control. These are protected shared files, so they were left untouched. This prevents calling the keyboard/accessible-markup pass clean. Actual VoiceOver/NVDA/Narrator, all-room keyboard traversal, chart patterns, rendered high-contrast pairs and Lexend/spacing were not checked.
